# Evidence sources beyond the collector

Work-summary captures GitHub, local Git and Jira activity per period. These
sources found evidence the captures alone did not surface.

## Jira

- **Comment bodies in the captures:** status updates, completion notes and
  decisions live in comments, so read them, not only issue titles. Search a
  capture's JSON for a comment id or a phrase, or use `acli jira workitem comment
  list --key KEY`.
- **Adoption of the person's tools:** search by tool name across all projects, for
  example `acli jira workitem search --jql 'text ~ "<tool-name>"'`. Others'
  issues that name the tool are adoption evidence. Follow their links, parents
  and subtasks.
- **Release outcomes:** read each release tracker's last comments. A closed
  tracker can be an abandoned attempt.
- **Who did the work:** an assignee is a lead, not proof. Look for a run record,
  an execution comment or authored PRs. When someone else operates the person's
  tooling, that is reuse by another engineer.

## Advisories

Vendor security advisories list fixed issue keys and CVEs (for example, Red Hat
errata pages at access.redhat.com/errata/RHSA-...). A Jira key of the person's in the fix list ties their work to a customer
delivery. For CVEs, require an exact fixed-version match to the person's PR, and
label anything weaker as probable.

## GitHub

- **CI ownership:** `scripts/workflow-authorship.sh <login> <owner/repo>...`
  gives sourced proportions. It reads full history, since files with long bot
  histories otherwise undercount.
- **Adoption:** code search for imports or includes of the person's work. Count
  verified use at the scope the criterion asks for, whether that is a team, an
  organization or a community. Forks and copies alone show no use.
- **Others' PRs crediting the person's tool:** for example, a PR body that says
  "generated by the ... skill".

## Older community work

- **IRC MeetBot minutes** (ircbot.wl.linuxfoundation.org/meetings/): chair,
  minutes, actions and votes.
- **LF Networking Confluence REST API:** project pages, election and release
  records.
- **Gerrit REST** (`/changes/?q=owner:...` and `reviewer:...`): authored and
  reviewed changes. Page through results, 100 at a time.
- **OpenStack specs and conference schedules (sched):** assignee lists and talks.

## Unreachable sources

Record a source that refuses automated reads as an evidence gap, with what it
would show. Don't work around the refusal.
